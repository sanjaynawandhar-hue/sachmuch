# Sachmuch on iPhone and Android

The Expo app now has a bilingual Discover feed, device-local bookmarks, source details, sharing, and language/appearance/haptics preferences. It uses real React Native screens, not a web wrapper.

## Run the interface immediately

Use Node supported by the installed React Native package (Node 22.13+, 24.3+, or 26+) and pnpm 10.34.5. From the repository root:

```sh
pnpm install --frozen-lockfile
EXPO_PUBLIC_SAMPLE_MODE=1 pnpm --filter @sachmuch/mobile exec expo start
```

Build/install on an iOS simulator with Xcode and CocoaPods:

```sh
EXPO_PUBLIC_SAMPLE_MODE=1 pnpm --filter @sachmuch/mobile exec expo run:ios
```

The sample preview is explicitly labelled. Its small bundled bilingual corpus exists for UI testing, never as a fallback for live server failures. Production bundles ignore sample mode. To use the already-built simulator app, keep Metro running and open Sachmuch in Device Hub (or Simulator on earlier Xcode).

Native directories are generated by Expo and ignored in Git. Regenerate them through `expo prebuild`/`expo run:ios`; app.json is the configuration source. Native dependencies match Expo SDK 57's compatibility recommendations.

## Connect the live content feed

1. Deploy this branch's web app with its existing server-only `DATABASE_URL` configured. The new `GET /api/feed` endpoint returns published facts only, in a versioned envelope capped at 300 bilingual records.
2. Copy `apps/mobile/.env.example` to `apps/mobile/.env.local`. Set `EXPO_PUBLIC_API_URL` to the HTTPS origin of that deployment, without a path or embedded credentials. Set `EXPO_PUBLIC_SAMPLE_MODE=0`.
3. Restart Metro after changing environment variables. Release bundles embed the public origin at build time.

For a local iOS simulator use `http://localhost:3000` and run `pnpm web` with the web database configured. A physical phone needs the Mac's private LAN address and a reachable server on the same network. HTTP is accepted only for loopback/private-LAN addresses in development; release builds require HTTPS.

Never put DATABASE_URL or Supabase service credentials in EXPO_PUBLIC variables. The phone talks only to the read-only web endpoint. Missing database configuration produces HTTP 503 with `FEED_UNAVAILABLE`; no sample facts or database errors leak through that endpoint.

## Reading behavior

Swipe up or down on the fact card to move through the native paged feed, or use the up/down buttons. Tap Read full fact for a separate scrollable reading view. Large text uses an expanded reading layout with accessible navigation. The mixed feed uses shared category-affinity ranking and reaches an explicit end rather than pretending to be infinite.

Hindi Discover includes complete Hindi facts only. Switching languages keeps the current fact when possible. Saved facts retain both available languages and their save date; missing Hindi is clearly labelled, with an explicit option to read English.

Bookmarks, preferences, and affinity are local to this installation. Saved copies are available offline; they are not live updates. There is no account or cross-device sync. Write failures leave the previous saved state intact and show an error. Unknown future storage versions are preserved rather than overwritten.

## Distribution

A simulator build is not a signed iPhone download. For TestFlight, configure an Apple Developer team, confirm rights to the existing `com.sachmuch.app` identifier, configure an Expo/EAS project if using cloud builds, and supply release API settings. App Store metadata, privacy disclosures and device signing remain release-owner steps. No account, billing integration or submission has been created automatically.

## Xcode 27 startup compatibility

Keep `expo-build-properties` configured with `ios.enableSceneSupport: true`. SDK 57 defaults to the old application lifecycle, which crashes at startup when built with Xcode 27 for iOS 27. Regenerate native files after changing this option. See [Expo’s migration guidance](https://github.com/expo/fyi/blob/main/ios-scene-lifecycle.md#staying-on-sdk-57-with-xcode-27).

The dedicated `apps/mobile/preview.js` entry provides explicitly labelled sample data through a context. Normal builds still use `index.js`; their production sample-mode guard is unchanged.

For a USB-installed offline debug preview, point the generated AppDelegate debug bundle URL to `Bundle.main.url(forResource: "main", withExtension: "jsbundle")`. After CocoaPods finishes, create `ios/.xcode.env.updates` with:

```sh
unset SKIP_BUNDLING
export ENTRY_FILE="$PROJECT_ROOT/preview.js"
export EXTRA_PACKAGER_ARGS="--dev false"
export SKIP_BUNDLING_METRO_IP=1
```

The production JavaScript flag is required: Expo's development JavaScript initializes server-only websocket tools and fails when embedded without Metro. Build the Debug native target with the selected signing team, then install over USB. These generated-native overrides are cleared by prebuild. Normal release builds embed JavaScript automatically and use the live API origin.

## Live deployment — 2026-10-15

The production feed is https://sachmuch-web-black.vercel.app/api/feed. The existing Supabase project was resumed, and the staged backend was validated before promotion. The public endpoint returned 153 published facts, including 140 complete Hindi translations across 9 categories.

The installed iPhone Release build uses `index.js`, `EXPO_PUBLIC_API_URL=https://sachmuch-web-black.vercel.app`, and `EXPO_PUBLIC_SAMPLE_MODE=0`. Its JavaScript is embedded, so Metro is unnecessary. This remains a developer-signed installation, not a TestFlight/App Store distribution.

The new app icon is `apps/mobile/assets/icon.png`. Vertical paging uses a native FlatList with fixed page geometry and a small render window. The full reading sheet keeps long text independent of feed swipes.

### Reading, love and music update (2026-10-15)

The feed uses native vertical paging, without bottom arrow buttons. Source details remain available from a small publisher link. The heart toggles a personal loved-fact ID; Settings displays the distinct total. Likes, bookmarks and music preferences persist locally, without an account or a global public like count.

A bundled original 48-second instrumental loop plays at 12% player volume by default. Settings offers off, 6% and 12%. The app mixes with other audio and pauses when inactive or backgrounded. It requests no microphone permission. Regenerate the original audio using `python3 apps/mobile/assets/music/generate.py`.

The mobile client requests `/api/feed?paged=1`, receiving up to 100 facts and a UUID `nextCursor`. Subsequent requests pass `after`. The server uses indexed UUID seek pagination; the app retains at most 600 recent records. Refresh restarts traversal and fetches updated fact content. The original unpaged endpoint remains compatible with earlier builds. The content corpus is currently 153 live facts, not millions. Growth depends on the existing ingestion pipeline and verification gates.

The scheduled importer was failing because pnpm/action-setup specified a version conflicting with packageManager. Remove the workflow override and allow the repository version. Repository Actions secret DATABASE_URL must contain the existing Supabase session-pooler connection string before ingestion can run. Never put it in source control or chat.
